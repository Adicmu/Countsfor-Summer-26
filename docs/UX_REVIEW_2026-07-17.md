# CountsFor — Road to 10/10: UX Review (July 17, 2026)

**Method.** Four specialist review agents audited the app in parallel — visual polish, copy/microcopy, accessibility (axe-core scans of 11 view states in both themes + scripted keyboard trials), and performance/hygiene (measured over a live local server with Playwright/curl) — working from a 36-screenshot inventory (every view × light/dark × desktop/tablet/mobile) plus the full codebase. Two further lenses (interaction flows, responsive breakpoints) were interrupted by an API session limit and are queued; visual + accessibility already cover part of that ground. Findings below were deduplicated and are ranked by user impact. **Severity** = how much it hurts users; **effort** = S/M/L.

**Already fixed in this cycle (committed, not yet pushed):** instant sign-in rendering with background session probe + server-waking states + keep-alive cron (`6e02232`), Scotty logo circle clipping (`f71e990`), full-width course card with larger type (`1a4d002`).

## 0. Fix-now: privacy & data exposure

These aren't UX polish — they're publicly-visible problems, listed first deliberately.

1. **[high/S] The entire 162 MB repo deploys to GitHub Pages** — `pages.yml` uploads `path: .`, so `conversation_log.txt` (306 KB, **confirmed publicly downloadable with HTTP 200**), `server.log`, backend source, `docs/` (91.5 MB of test screenshots/recordings), `Testing/`, sprint plans, and branding files are all on the public internet. Upload a filtered artifact instead (html/js/css/assets + the two data JSONs). `.github/workflows/pages.yml`
2. **[high/S] Delete `main_bundle.js`** — 5.0 MB, tracked in git, served publicly, referenced by exactly zero files.
3. **[high/S] Delete or exclude `data_all_courses.json`** — 21.8 MB near-duplicate of `data/courses.json`; doubles the data footprint for nothing.

## 1. Performance (what users feel as "slow")

4. **[high/M] The app boots by downloading 21.8 MB of `courses.json`** (~1.1 MB gzipped, 6,334 courses; 48 MB JS heap after parse). Descriptions alone are 1.5 MB. Slim the boot payload (strip `soc_sections`/`offerings`/`description` into a lazy per-course fetch). `js/api.js` `fetchAllCourses()`
5. **[high/S] `API_BASE` points at a DNS-dead host** (`countsfor.qatar.cmu.edu` — fails resolution in 0.28s), so every boot burns a failed network attempt before falling back, and it disagrees with the Render URL used everywhere else. Align the constants. `js/api.js:9`
6. **[med/M] The requirement tree re-renders all ~6,300 DOM nodes on every keystroke** in tree search (no debounce, unlike the other three search boxes) and on every bookmark/flag/filter/expand action (8 call sites). Debounce tree search; patch single nodes for bookmark/flag state. `js/app.js:1509`, `renderTree` at `:3004`
7. **[med/S] Inconsistent cache-busting** — `app.html` versions 4 files with hand-written `?v=` tags but `utils.js` and `profile.js` ship unversioned, so returning users can run a stale `profile.js` against a new `app.js` (real breakage). Stamp one build version (e.g. commit SHA) on every asset in CI. `app.html:46-50`
8. **[med/S] Google Identity Services (266 KB) loads for every guest** who by definition never signs in. Inject it on demand when sign-in UI opens. `index.html`, `app.html`
9. **[med/S] Render-blocking Google Fonts CSS** on the landing page; self-host the two fonts or load async. `index.html:26-28`
10. **[med/S] Favicons are full-size illustrations** (~117 KB combined, one is 2392×1927) served from `docs/`; export proper 32/180px icons into `assets/`. `app.html:9-10`, `index.html:24-25`
11. **[med/S] `scotty-head.png` is 6363×6363 displayed at 72px** — the decode buffer is ~162 MB RGBA on mobile. Resize to ≤200px (~5 KB). `assets/img/scotty-head.png`
12. **[med/M] No minification** — 386 KB raw JS+CSS; an esbuild/lightningcss step in the Pages workflow would cut 30-40% + parse time.

## 2. Dark-theme parity (most visible visual bugs)

13. **[high/S] The "YOUR NOTE ON THIS COURSE" panel stays cream-colored in dark mode** — `--cf-parchment: #F5F0EA` has no dark override; it's the most jarring parity break in the app. `css/styles.css:11` (token), `:3495` (usage)
14. **[high/S] The note textarea renders white-on-dark-card** — `.wl-note-input` never sets `background`/`color`, so the UA default white shows. `css/styles.css:3500`
15. **[high/M] CMU red `#C41230` used as text on dark surfaces fails contrast everywhere it appears** — navbar wordmark 3.17:1, "Explore other courses" / "Save course" 2.75:1, role badge 2.73:1, tree rule chips 2.76:1. Dark-theme text tokens (`--major-*-text`, e.g. `#F87171`) already exist but these rules bypass them. `css/styles.css:3106, :3437, :1168`
16. **[med/S] "IN PERSON"/"REMOTE" pills on the course card use hardcoded light pastels** that glow in dark mode — while the sibling `.dm-*` classes for the same concept have proper dark overrides. Unify. `css/styles.css:3020-3021` vs `:1255-1262`
17. **[med/S] The REQUIRED chip is hardcoded `#1f2937/white`** — loudest element in light theme, nearly invisible in dark. Tokenize. `css/styles.css:3010`
18. **[med/S] "+18 more sections" uses light-theme blue in dark mode** (3.22:1) instead of the existing `--major-ba-text` token. `css/styles.css:3017`

## 3. First impressions & trust

19. **[high/M] The empty sign-in email field looks like an error on first paint** — the field is autofocused and `:focus-visible` uses the *same red border* as the invalid state. New users' first impression is "I already did something wrong." Differentiate focus (neutral ring) from invalid (red), or drop the autofocus. `css/landing.css:446-452`, `js/landing.js:629`; same oversized red focus halo on the home search. `css/styles.css:2371-2374`
20. **[high/S] The Google recovery button renders in the browser's locale** ("Continuar con Google") while the instructions say "use **Continue with Google** below" — pass `locale: 'en'` to `renderButton`, or reference it generically. `js/landing.js` `mountGoogleRecover`
21. **[med/M] Prereq line renders raw data artifacts** — "15-112 [] at least C" reads as a bug and undermines trust in the requirement data itself. Clean to "15-112 (minimum grade C)". `js/app.js:2786`
22. **[med/S] Search placeholder visibly truncates** ("…e.g. 15-122 or Probabi") — shorten to "Search by course number, title, or category"; the example chips below already demonstrate. `js/app.js:2324`

## 4. One feature, four names (copy & consistency)

23. **[high/M] The save feature is called "wishlist", "Saved for later", "Save courses", and "Student favorites"** across toasts, nav, and faculty views. Standardize on **"saved courses"** everywhere. `js/app.js:3347, :3375, :3364, :2477, :1362`
24. **[high/S] Saved-courses hint promises a "share favorites" action that has no UI** — rewrite: "Add a note to each course — your advisor can see your saved courses and notes." `js/app.js:3437`
25. **[high/S] Guest banner "Saved locally on this device only" is a subjectless fragment** — rewrite: "Anything you save stays on this device — sign in to keep it." `js/app.js:1308`
26. **[med/S] The explorer is called "requirement tree", "requirement map", and "category browser"** in three places — pick one ("requirement tree"). `js/app.js:1326, :2044`
27. **[med/S] Two different server-unreachable messages** — the new landing copy ("it may be waking up. Try again in ~30s.") vs the old app copy ("wait ~30s and refresh"). Use the landing version in both. `js/app.js:838`
28. **[med/S] "2 slots" is internal vocabulary** — students don't know what a slot is; use "counts in 2 requirements". Course card header.
29. **[med/S] "BA/BS" read as Bachelor of Arts/Science to anyone outside CMU-Q** — the faculty home hero should spell out "Business" and "Biological Sciences" (the auth panel already does). `js/app.js` home hero
30. **[med/S] Four different access-gate toast phrasings** — standardize on "Sign in as faculty to [action]." `js/app.js:2633, :3506, :3586, :3590`
31. **[med/S] "No data" empty state in the explorer is a dead end** — "No requirement data for this program yet — pick another major above." `js/app.js:3026`
32. **[med/S] Raw error internals shown to students** — "Failed to load data: NetworkError…" → "Couldn't load courses — check your connection and refresh." (console.log the details). `js/app.js:263`
33. **[low/S] Grammar/pluralization** — "Downloaded 1 courses" (`js/app.js:3159`), "· 1 students" (`:3532`); "Tap the bookmark" on desktop (`:3406`); lone "login" vs app-wide "sign in" (`:3871`); mixed toast punctuation (~30 toasts); duplicated "no reset email needed" reassurance on the forgot panel; term codes "F25 · M25" have no key (tooltip or spell out).
34. **[low/S] Section-list empty state doesn't point at the cause** — append "— try another semester or clear the filters above." `js/app.js:2794`

## 5. Accessibility (WCAG 2.1 AA)

*Keyboard access is the big theme: the landing forms are genuinely good; the app views are not.*

35. **[high/M] The requirement tree is keyboard-unusable** — expand/collapse rows are plain divs (no tabindex/role/aria-expanded), driven only by click delegation. `js/app.js:3065, :3088, :1565-1575`
36. **[high/S] "Create account" is unreachable by keyboard** — roving `tabindex="-1"` with no arrow-key handler; an 18-stop Tab walk never reaches the tab. Registration is impossible without a mouse. `js/landing.js:424`
37. **[high/M] The search typeahead has zero ARIA** — no combobox/option roles, no live region; arrow-key highlight is visual-only, and the scrollable dropdown never scrolls the focused item into view (selection can move below the fold invisibly). `js/app.js:2324, :2062, :2081-2087`
38. **[high/M] Focus is destroyed on every view swap** — innerHTML replacement drops focus to `<body>`; only two `.focus()` calls exist in all of app.js. `js/app.js:1331, :2156`
39. **[med/S] Badge contrast failures in both themes** — white on IS-amber 3.18:1, white on BS-green 3.76:1 at 10.5-12px (`css/styles.css:2983-2985`); amber rule chips 4.38:1 (`:1168`); "major" suffix in the role badge 4.29:1 (`:2226`).
40. **[med/S] App toasts are never announced** — `showToast` has no `role`/`aria-live` (the landing toast does it correctly — copy that). `js/utils.js:39-45`
41. **[med/M] No `<main>` landmark and zero headings in the app views** — course code/title are divs; screen-reader structural navigation is impossible. `js/app.js:2853-2854`
42. **[med/M] Dialogs don't manage focus** — flag modal and directory panel have correct roles and Escape handling but never move, trap, or restore focus. `js/app.js:3611, :3809`
43. **[med/S] Misc keyboard gaps** — navbar brand is a click-only div (`js/app.js:1335`); explorer course rows are click-only divs (`:2720`); panel resizer lacks `aria-valuenow` (`:1378`).
44. **[low/S] Also worth fixing** — theme toggle announces as "crescent moon" (`js/app.js:1359`); no `prefers-reduced-motion` block in styles.css (landing.css has one); several sub-24px touch targets on mobile ("+N more sections" is 95×22); tree save/flag actions are hover-revealed (`opacity:0`) so touch devices never see them (`css/styles.css:3365-3376`); hero search input's only accessible name is its disappearing placeholder.

## 6. Visual polish

45. **[med/S] Search dropdown is center-aligned** (inherits `text-align:center` from the hero) — course titles float mid-row, breaking column scan. Add `text-align:left` to `.home-typeahead`. `css/styles.css:2332, :2401`
46. **[med/S] The "Save course" pill has a detached red arc** — `border-left: 3px` on a fully-rounded pill renders as a floating "(" crescent. `css/styles.css:3961-3963`
47. **[med/S] The flag button's amber accent never renders** — `border-left` set then immediately overridden by `border-color` two lines later. `css/styles.css:3972-3979`
48. **[med/M] Navbar collapses badly at ~820px** — the semester select overlaps the wordmark; chips vanish. Needs a wrap/priority strategy. (see `inventory/explorer-split-light-tablet.png`)
49. **[med/S] "CMU-Q" wraps to "CMU-"/"Q" on mobile** — add `white-space:nowrap`. `css/styles.css:337`
50. **[med/S] Slot names truncate even at full desktop width** ("Cultural & Global Understandi…") — the label shares a nowrap line with the chip; allow 2-line wrap. `css/styles.css:3002`
51. **[low/S] Smaller polish** — 15+ solid-red download buttons per explorer screen outshout navigation (mute until hover); equal-height "Counts for" cards leave voids in 1-slot cards; "Recently updated mappings" card is sparse next to dense siblings; wishlist header wraps awkwardly in the split pane; the pink "CS — YOUR MAJOR" banner clips its subtitle on mobile; emoji icons (🔖📁🌙) mixed with the SVG icon set render differently per platform — standardize on SVG.

## 7. Code hygiene (developer-facing, indirect user impact)

52. **[med/S] Pre-existing failing unit test** — `annotateDoubleCounters: focused-dual marks courses fulfilling both programs` (fails on clean main; verified pre-dates this cycle). Also `scripts/run-data-tests.js` never loads `tests/profile.test.js`.
53. **[med/M] Duplicate auth UI implementations** in both `landing.js` and `app.js` (two sign-in/register/forgot/reset stacks to keep in sync).
54. **[low/S] Stale docs** — `backend/README.md` says "scaffold only, no running code" and names port 5000 while the frontend expects 5050; `Testing/` is an obsolete prototype; wireframe PNGs and scaffold JSONs at root are unreferenced.
55. **[low/S] Offline `cf_flags` accumulate with no cap** until first successful sync — add a modest cap (~200). `js/app.js:3558-3561`

## What's already strong (keep it)

Recovery-path copy is excellent in places ("Saved locally — sync to server failed (will retry next sign-in)", the guest flag toast, the "Coming soon" empty state with its data-contribution CTA) — use these as the house style. Landing forms have real labels, autocomplete, `aria-describedby` error wiring. Event delegation is clean (no listener leaks measured; heap stable at ~48 MB). Dark-theme secondary/tertiary text tokens were already remediated (7.5:1 / 11:1). The panel resizer's arrow-key support is a nice touch.
